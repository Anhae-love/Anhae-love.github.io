# 일일 파이프라인 — 실행 지시

너는 HCI 인스타그램 계정의 콘텐츠를 **무인으로** 제작한다.
사람은 지금 자고 있다. 도중에 질문하지 마라. 막히면 멈추고 기록을 남겨라.

프로젝트 루트는 이 파일의 상위 폴더다. 아래 경로는 전부 루트 기준이다.

---

## 먼저 읽을 것

1. `HCI_인스타그램_콘텐츠_프롬프트_v3.md` — **무엇을 쓸지.** 이게 본체다
2. `automation/content_contract.md` — **어떤 형태로 쓸지**
3. `automation/sample_content.json` · `automation/sample_facts.json` — 작동하는 실제 예시
4. `state/index.jsonl` — 과거 발행 이력 (없으면 첫 실행)

---

## 0. 준비

오늘 날짜와 요일을 확인한다. v3 요일표에서 오늘의 주제를 찾는다.

`state/index.jsonl`을 읽어 다음을 배제 목록으로 삼는다.

- 이미 다룬 `source_url` / `source_title` (같은 논문 재탕 금지)
- 최근 60일 안에 쓴 `object_name` (오브젝트 재사용 금지)
- 최근 14일 안에 쓴 `accent_color` (색 반복 방지)

작업 폴더를 만든다: `output/<YYYYMMDD>_<주제 요약>/`
주제 요약은 공백 대신 `_`, 파일명 금지문자 제외, 40자 이내.

---

## 1. 조사와 선정

v3의 '자료 조사' 절을 그대로 따른다. 최소 8개 후보를 검토하고 하나를 고른다.

**검색 결과 제목만 보고 쓰지 않는다.** 원 출처를 연다.
원문에 접근하지 못했으면 `source_access_status`에 정직하게 적는다.
접근 못 한 논문으로 카드를 만들지 마라 — 그 경우 다른 후보로 간다.

선정문을 완성한다. 이 문장의 "하지만 ~까지 확인한 것은 아니다" 부분이
뒤에 나올 5장 '오해 방지'의 재료가 된다.

---

## 2. facts.json — 사실을 먼저 얼린다

**카피를 쓰기 전에 이것부터 쓴다. 순서를 바꾸지 마라.**

작업 폴더에 `facts.json`을 만든다. 형식은 `automation/content_contract.md`의
'facts.json' 절에 있다. 원문을 열어둔 채로 쓴다.

- 모든 `findings[].source_quote`는 **원문에 실제로 있는 문장**이어야 한다.
  기억으로 쓰지 마라. 지어낸 인용은 이 파이프라인에서 가장 중대한 위반이다.
- `kind`를 정확히 고른다. 특히 **유의하지 않은 결과는 반드시 `null_result`**다.
  이 필드 하나가 카드에서 쓸 수 있는 표현을 결정한다.
- `scope`에 그 결과가 어디까지 해당하는지 적는다. 전체 분석인가, 하위 조건인가.
- `not_measured`에 연구가 확인하지 않은 것을 적는다. 5장의 재료가 된다.

> **이 단계에서 카피를 쓰지 마라.** 훅도, 제목도, 비유도 생각하지 마라.
> 지금은 원문이 무엇을 말했는지만 기록한다.
> 사실과 서술을 같은 호흡에 쓰면 서술이 사실을 밀어낸다. 이 게이트는 그래서 있다.

---

## 3. content.json 작성

`automation/content_contract.md`의 계약대로 작업 폴더에 `content.json`을 쓴다.

**이제 원문이 아니라 `facts.json`을 보고 쓴다.** 카드에 올라가는 모든 수치는
거기 있어야 한다. 없으면 카피를 고치는 게 아니라, 원문으로 돌아가 확인하고
`facts.json`에 추가한다.

`facts.json`에 `null_result`가 하나라도 있으면 **"같았다 · 동일 · 차이가 없었다"를
쓸 수 없다.** "뚜렷하지 않았다 · 유의하지 않았다"로 쓴다.
차이를 확인하지 못한 것을 같다고 쓰는 건 귀무가설을 입증으로 뒤집는 것이다.

hero_copy의 동사를 하나하나 확인한다. 상관 연구에 "바꿨다", "만들었다",
"때문에"를 쓰면 이 단계에서 이미 실패다.

---

## 4. 자가 검사

```bash
python automation/render.py "output/<폴더>/content.json" --check-only
```

종료 코드 `2`면 `output/<폴더>/render_report.json`의 `errors`를 전부 고치고 다시 돌린다.
**통과할 때까지 5단계로 넘어가지 않는다.** `warnings`도 가능하면 고친다.

---

## 5. GPT 교차검증

```bash
python automation/verify.py --dir "output/<폴더>" --attempt 1
```

Codex(GPT)가 원문을 직접 대조하고 판정한다. 5~10분 걸린다.

> **이 명령을 백그라운드로 돌리지 마라.** 포그라운드에서 끝까지 기다려라.
> 너는 일회성 헤드리스 세션이다. 턴이 끝나면 너도 죽고, 백그라운드에 띄워 둔
> codex 도 같이 죽는다. 그러면 검증도 카드도 없이 빈 폴더만 남는다.
> 10분 기다리는 건 정상이다. 멈춘 게 아니다. 타임아웃은 스크립트가 알아서 건다.

결과는 `output/<폴더>/verdict.json`.

### 종료 코드에 따라

**`0` (pass)** → 6단계로 간다.

**`10` (revise)** → `verdict.json`의 `issues`를 반영한다.

- `fix` 필드에는 갈아끼울 실제 문구가 들어 있다. 그대로 쓸 수 있으면 그대로 쓴다.
- `blocker`와 `checklist` fail은 **전부** 고친다. `minor`는 판단해서 고친다.
- 지적이 사실과 다르다고 판단되면 고치지 말고, 왜 그런지를
  `content.json`의 `verification_items`에 근거와 함께 남겨라.
  다음 검증에서 GPT가 그걸 읽는다.
- 고친 뒤 **4단계 자가 검사를 다시 통과시키고**, `--attempt 2`로 재검증한다.

**재검증은 최대 2회까지다.** `--attempt 3`이 또 pass가 아니면 6단계로 가지 않는다.
7단계로 건너뛰어 `STATUS`를 `needs_human`으로 남기고 종료한다.

**`20` (reject)** → 이 주제는 버린다. 카드를 만들지 않는다.
`STATUS`를 `rejected`로 남기고, 1단계에서 검토했던 2순위 후보와 reject 사유를
`NOTES.md`에 적어 둔다. **다른 주제로 다시 시작하지 마라** — 새벽에 무한정 돌릴 이유가 없다.
사람이 아침에 보고 결정한다.

**`30`** → codex 실행 실패. `_codex_log.txt`를 확인하고,
일시적 오류로 보이면 한 번만 재시도한다. 그래도 실패하면
`STATUS`를 `verify_failed`로 남기고 종료한다.
**검증 없이 카드를 만들지 마라.** 이 게이트를 건너뛰는 경우는 없다.

---

## 6. 카드 제작

```bash
python automation/render.py "output/<폴더>/content.json"
```

`slide_1~6.png`, `slide_1~6.svg`, `caption.txt`, `alt_texts.txt`가 생긴다.

생성된 PNG를 **직접 열어서 본다.** 렌더가 통과했다고 그림이 맞는 건 아니다.

- 글자가 잘리거나 겹치지 않았는가
- 오브젝트가 카드 밖으로 나가지 않았는가
- 6장을 넘겨볼 때 오브젝트의 변화가 실제로 읽히는가
- 1장만 보고 스크롤을 멈출 만한가

문제가 있으면 `content.json`을 고치고 다시 렌더한다.
**문구의 의미를 바꾸는 수정이면 5단계 재검증이 필요하다.**
좌표·줄바꿈·크기만 고치는 거라면 재검증 없이 진행해도 된다.

---

## 7. 마무리

`output/<폴더>/STATUS`에 한 줄로 상태를 적는다:
`awaiting_human_review` / `needs_human` / `rejected` / `verify_failed`

`awaiting_human_review`인 경우에만 `state/index.jsonl`에 한 줄을 덧붙인다:

```json
{"date":"","weekday_category":"","content_title":"","source_title":"","source_url":"","object_name":"","accent_color":"","verdict":"pass","attempts":1,"folder":""}
```

마지막으로 `output/<폴더>/NOTES.md`에 사람이 아침에 읽을 것을 적는다.

- 오늘 고른 주제와 이유
- 탈락한 후보와 사유
- GPT가 지적했고 네가 고친 것
- GPT가 지적했지만 **고치지 않은 것과 그 이유**
- 게시 전 사람이 반드시 확인할 것

## 진행 기록

단계에 들어갈 때마다 `output/<폴더>/PROGRESS.log`에 **한 줄씩** 덧붙인다.

```
2026-09-21 19:47 | 1.조사 | 후보 8건 검토 완료, 선정: <논문 제목>
2026-09-21 19:49 | 2.사실 | facts.json 작성 — findings 7건
2026-09-21 19:52 | 3.작성 | content.json 작성
2026-09-21 19:53 | 4.자가검사 | 통과 (오류 0, 경고 0)
2026-09-21 19:53 | 5.검증 | codex 호출 attempt 1 — 대기 중
2026-09-21 20:01 | 5.검증 | verdict=pass
2026-09-21 20:02 | 6.제작 | 카드 6장 렌더 완료
```

새벽에 실패하면 이 파일이 **어느 단계에서 끊겼는지 알려주는 유일한 단서**다.
다음 단계로 넘어가기 전에 쓴다. 나중에 몰아서 쓰지 마라.

이미 `PROGRESS.log`가 있는 폴더를 만났다면 **중단된 실행을 이어받는 것**이다.
처음부터 다시 조사하지 말고, 마지막 줄 다음 단계부터 시작한다.
`facts.json` 과 `content.json` 이 있고 자가검사를 통과했다면 5단계 검증부터 이어가면 된다.

## 절대 하지 않을 것

- **인스타그램에 자동 발행.** 이 파이프라인은 발행하지 않는다. 계정 로그인도 하지 않는다
- 검증 게이트 건너뛰기
- **`facts.json` 없이, 또는 카피를 먼저 쓰고 나서 `facts.json` 을 채우기.** 순서가 전부다
- 원문을 열어보지 않고 카드 만들기
- **`source_quote` 를 기억으로 쓰기.** 원문에 없는 인용은 최악의 위반이다
- 접근 못 한 URL을 `source_url`에 적기
- 사람에게 질문하고 응답 기다리기 (아무도 없다)
- `output/` 밖의 기존 파일 수정. `state/index.jsonl` 추가만 예외
- **오래 걸리는 명령을 백그라운드로 띄우고 턴 끝내기.** 너와 함께 죽는다
